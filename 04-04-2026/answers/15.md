### RCA: BaseAgent Hallucinated `Attributes` Column in `otel_logs` Query

#### TL;DR

BaseAgent's first SQL query used a column called `Attributes` that **does not exist**
in `otel_logs`. ClickHouse rejected it instantly. The agent self-corrected, but the
root problem is that the LLM is guessing column names because it was never given the
actual table schema — and there are two places in the code where that schema is
missing.

#### What Broke and Why

When BaseAgent was dispatched to investigate a production error, it generated this
SQL as its very first action:

```sql
-- INVALID — column does not exist
SELECT Body, Timestamp, ServiceName, SeverityText, Attributes
FROM otel_logs
WHERE Body LIKE '%no spac%'
AND Timestamp > now() - INTERVAL 24 HOUR
```

You can see the agent logging the bad query before it was sent to ClickHouse:

```

ClickHouse immediately rejected it:

  "error": "Unknown expression identifier `Attributes` in scope SELECT Body,

```

One second later the agent self-corrected and reissued with `LogAttributes`, which
is the right column:

##### Why the Agent Got It Wrong

There are two places in the codebase where schema information should appear but
doesn't.

**1. `mewtwo/src/agents/base.agent.ts` — `buildSystemPrompt()`**

The system prompt gives the LLM an example query but only ever shows four safe
columns. `LogAttributes`, `SpanAttributes`, and `ResourceAttributes` are never
mentioned:

```typescript
private buildSystemPrompt(): string {
    return `You are a research agent investigating production errors. You have access to production logs via ClickHouse.

Your core task is to investigate the root cause of the error and provide a detailed report. Do not focus on solutioning.

Example first query:
SELECT Body, Timestamp, ServiceName, SeverityText 
FROM otel_logs 
WHERE Body LIKE '%${this.run.foamTelemetry?.exceptionMessage?.includes(':') ? this.run.foamTelemetry?.exceptionMessage?.split(':').pop()?.trim().slice(0, 30) : 'error'}%' 
AND Timestamp > now() - INTERVAL 24 HOUR 
ORDER BY Timestamp DESC 
LIMIT 50

## Tools

- **queryOtel**: Query production logs/traces (otel_logs, otel_traces tables in ClickHouse)
```

When the LLM needs to query attributes it has no example to follow, so it guesses
`Attributes`.

**2. `mewtwo/src/agents/tools/query-otel.tool.ts` — tool description and input schema**

The tool description names the tables but provides zero column information:

```typescript
export function createQueryOtelTool(ctx: ToolContext) {
    return tool({
        description: `Query OpenTelemetry logs or traces from ClickHouse (otel_logs, otel_traces tables). Always add a LIMIT to the query.`,
        inputSchema: schema,
```

And the `sql` field in the input schema gives the LLM nothing to work with beyond
"write SQL":

```typescript
const schema = z.object({
    intent: z.string().describe('What you are looking for'),
    sql: z
        .string()
        .describe(
            'ClickHouse SQL query for otel_logs or otel_traces. Include time filter and LIMIT.',
        ),
});
```

Neither location mentions `LogAttributes`, `SpanAttributes`, or `ResourceAttributes`.
The LLM receives the table names with zero schema grounding from both the system
prompt and the tool definition, so it invents `Attributes` — and it will keep doing
this until one of these two locations is fixed.

This is the same hallucination documented in eval `foam-agent-otel-traces-invalid-column`
(run `f0aaca3e`), where the agent did the exact same thing against `otel_traces`:

```sql
-- INVALID — same hallucination, different table
SELECT SpanName, StatusCode, StatusMessage, Attributes, Timestamp
FROM otel_traces
WHERE Attributes LIKE '%git%'
```

##### Correct Schema

| Table | Correct Column | Type |
|---|---|---|
| `otel_logs` | `LogAttributes` | `Map(String, String)` |
| `otel_traces` | `SpanAttributes` | `Map(LowCardinality(String), String)` |
| `otel_traces` | `ResourceAttributes` | `Map(LowCardinality(String), String)` |
| `otel_traces` | `Events.Attributes` | `Array(Map(...))` |
| `otel_traces` | `Links.Attributes` | `Array(Map(...))` |

#### Fix

Add the schema above to both `buildSystemPrompt()` in `base.agent.ts` and the `sql`
field description in `query-otel.tool.ts`. Either location alone would likely prevent
the hallucination — both should be fixed.
