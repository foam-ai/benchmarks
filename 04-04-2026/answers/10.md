### RCA: Vertex AI Fallback Model 404 in `mewtwo` Issue Solver (Run `8c79a0d2`)

#### TL;DR

The `bubblesModel` fallback chain in `mewtwo` Issue Solver exhausted its primary models (`CLAUDE_SONNET_4`, `CLAUDE_HAIKU_45`) and fell through to `CLAUDE_SONNET_37`. The `anthropic()` helper attempted to route this model through Vertex AI using the mapping in `ANTHROPIC_TO_VERTEX`, but project `foam-ai-452314` lacks entitlement to `claude-3-7-sonnet@20250219` on Vertex AI — the model was deprecated in November 2025 and restricted to existing customers only. The Vertex endpoint returned 404 NOT_FOUND, but `FallbackModel.retry` treated this as a retryable error and looped instead of falling through.

#### What Broke and Why

The `anthropic()` helper in `mewtwo/src/services/ai-sdk-registry.ts` builds a fallback chain with this order: **Direct API → Vertex AI → Bedrock**. For `CLAUDE_SONNET_37`, the Vertex model ID is resolved from `ANTHROPIC_TO_VERTEX`:
```typescript
// mewtwo/src/services/ai-sdk-registry.ts
const ANTHROPIC_TO_VERTEX: Record<string, string> = {
  // ...
  [CLAUDE_SONNET_37]: 'claude-3-7-sonnet@20250219',  // ← this mapping resolves the failing endpoint
  // ...
};
```

That mapping produced the following endpoint, which returned 404 on every call:
```
# INVALID — project foam-ai-452314 does not have access to this publisher model
https://aiplatform.googleapis.com/v1/projects/foam-ai-452314/locations/global/publishers/anthropic/models/claude-3-7-sonnet@20250219:streamRawPredict

{"error": {"code": 404, "message": "Publisher Model `projects/foam-ai-452314/locations/global/publishers/anthropic/models/claude-3-7-sonnet@20250219` was not found or your project does not have access to it.", "status": "NOT_FOUND"}}
```

The `anthropic()` helper pushes models in this order:
```typescript
// mewtwo/src/services/ai-sdk-registry.ts — anthropic() helper
function anthropic(modelId: string) {
  const models = [];

  models.push(anthropicDirect(modelId));           // 1. Direct API

  const vertexModelId = ANTHROPIC_TO_VERTEX[modelId];
  if (vertexModelId) {
    models.push(anthropicVertex(vertexModelId));   // 2. Vertex AI  ← 404 here
  }

  const bedrockModelId = ANTHROPIC_TO_BEDROCK[modelId];
  if (bedrockModelId) {
    models.push(anthropicBedrock(bedrockModelId)); // 3. Bedrock
  }

  return createFallback({ models: asV2Models(models), ... });
}
```

The `bubblesModel` role chain includes `CLAUDE_SONNET_37` as its third-position fallback:
```typescript
// mewtwo/src/services/ai-sdk-registry.ts — bubblesModel
const bubblesModel = createFallbackChain(
  [anthropic(CLAUDE_SONNET_4), anthropic(CLAUDE_HAIKU_45), anthropic(CLAUDE_SONNET_37)],
  'bubbles',
);
```

When the run reached `anthropic(CLAUDE_SONNET_37)`, the inner `FallbackModel` for that model resolved Vertex AI as the first non-direct provider to try. The Vertex endpoint returned 404 — a non-transient, access-denied failure — but `FallbackModel.retry` has no logic to distinguish 404 from a retryable 5xx. It looped:
```
AI_APICallError: Not Found
  at postToApi
  at AnthropicMessagesLanguageModel2.doStream
  at async FallbackModel.retry   ← first retry against same Vertex endpoint
  at async FallbackModel.retry   ← second retry, still 404
```

The exception propagated up without ever reaching the Bedrock fallback for `CLAUDE_SONNET_37`.

#### Understanding Vertex AI Model Lifecycle: Entitlement, Deprecation, and Shutdown

Vertex AI partner models follow a three-stage lifecycle that differs from the direct Anthropic API:

| Stage | Definition | Behavior |
|-------|------------|----------|
| **Entitlement** | Project-level permission granted by clicking "Enable" on a model card in Model Garden. Requires the `Consumer Procurement Entitlement Manager` IAM role. | Projects without entitlement receive 404 NOT_FOUND on all API calls. |
| **Deprecation** | Model is functional but no longer recommended. A shutdown date is assigned. | On Vertex AI, new entitlements are frozen — only "existing customers" retain access. New projects are permanently locked out. |
| **Shutdown** | Model is fully retired. | All API calls fail for all projects, regardless of prior entitlement. |

**Claude 3.7 Sonnet Timeline on Vertex AI:**
- **Feb 25, 2025**: Launched in Preview
- **Mar 18, 2025**: Went GA (model ID: `claude-3-7-sonnet@20250219`)
- **Nov 11, 2025**: Deprecated — restricted to "existing customers only". Those who have enabled the model before the deprecation date.
- **May 11, 2026**: Scheduled shutdown

Project `foam-ai-452314` likely never enabled Claude 3.7 Sonnet before November 11, 2025, leaving `CLAUDE_SONNET_37` unavailable on Vertex.

**Key distinction from Anthropic Direct API:** On the direct API, all users retain access to deprecated models until retirement. On Vertex AI, deprecation immediately blocks new projects, making entitlement status the determining factor for access.

**Sources:**
- [Vertex AI Partner Model Deprecations](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/deprecations/partner-models)
- [Anthropic Model Deprecations](https://docs.anthropic.com/en/docs/resources/model-deprecations)
- [Vertex AI Partner Models — Entitlement Requirements](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/partner-models/use-partner-models)

#### Fix

Remove `CLAUDE_SONNET_37` from `ANTHROPIC_TO_VERTEX` in `mewtwo/src/services/ai-sdk-registry.ts`. The model is in a deprecation/entitlement-gated state on Vertex for this project, and Bedrock already has a working mapping (`us.anthropic.claude-3-7-sonnet-20250219-v1:0`). Additionally, add a 404 short-circuit in the `onError` handler of the `anthropic()` helper so that NOT_FOUND responses skip further retries on the same provider and fall through to the next one immediately:
```typescript
// mewtwo/src/services/ai-sdk-registry.ts — ANTHROPIC_TO_VERTEX
const ANTHROPIC_TO_VERTEX: Record<string, string> = {
  [CLAUDE_SONNET_45]: 'claude-sonnet-4-5@20250929',
  [CLAUDE_SONNET_4]:  'claude-sonnet-4@20250514',
  [CLAUDE_OPUS_41]:   'claude-opus-4-1@20250805',
  [CLAUDE_OPUS_4]:    'claude-opus-4@20250514',
  // [CLAUDE_SONNET_37]: 'claude-3-7-sonnet@20250219',  ← remove this line
  [CLAUDE_HAIKU_35]:  'claude-3-5-haiku@20241022',
  [CLAUDE_HAIKU_3]:   'claude-3-haiku@20240307',
};
```
