### RCA: Unauthenticated User Hits Issues Page — Null User Causes Server Component Crash

#### TL;DR

An unauthenticated user navigated to `/issues`. The Next.js Server Component called `getUser()`, which returned `null` due to a missing or expired session cookie. The page then accessed `user!.customerId` using TypeScript's non-null assertion operator with no null check, throwing a `TypeError`. Next.js caught the error and suppressed the message in production.

#### What Broke and Why

The browser telemetry captured the suppressed error at `sdk.foam.ai/issues`:

```
Error: An error occurred in the Server Components render.
The specific message is omitted in production builds to avoid leaking sensitive details.
```

The underlying error is `TypeError: Cannot read properties of null (reading 'customerId')`. In `app/(platform)/issues/page.tsx`, `getUser()` is called and the result is immediately passed to `getData` and `getServiceOptions` using the non-null assertion operator:

```typescript
const { user } = await getUser();
const { issues, pagination, status } = await getData(user!.customerId, params);
const serviceOptions = await getServiceOptions(user!.customerId);
if (status === 401) {        // TOO LATE — never reached
    return redirect('/login');
}
```

`getUser()` explicitly can return `user: null` when session cookies are missing or authentication fails. The non-null assertion operator suppresses the TypeScript compiler warning without adding any runtime safety, so when `user` is `null` the dereference throws immediately. The 401 redirect check comes after — it is never reached.

The same bug exists in `app/(platform)/issues/[issueId]/page.tsx`. Other platform pages like `app/(platform)/setup/page.tsx` already handle this correctly by checking authentication status before proceeding:

```typescript
if (!isLoggedIn || !customer?.companyName) {
    return redirect(routes.login);
}
```

The issues pages were missing this guard entirely.

#### Fix

**Permanent:** Add authentication checks to `issues/page.tsx` and `issues/[issueId]/page.tsx` before any `user` dereference. Check if `user` is null or `isLoggedIn` is false and redirect to `/login`:

```typescript
const { user, isLoggedIn } = await getUser();
if (!isLoggedIn || !user) {
    return redirect('/login');
}
```

This eliminates the non-null assertion entirely and ensures unauthenticated users are redirected before `customerId` is ever accessed.
