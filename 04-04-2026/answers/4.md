### RCA: queryOtel Tool Blindly Appends LIMIT to DDL Statements, Causing ClickHouse Syntax Error — Agent Recovers

#### TL;DR

This is a tool bug, not an LLM hallucination. SimpletonAgent generated a perfectly valid `DESCRIBE otel_logs` query, but the `queryOtel` tool blindly appended ` LIMIT 500` to it. The ClickHouse client then appended ` FORMAT JSONEachRow`, producing a malformed query that ClickHouse rejected. The tool's try-catch block caught the error and returned it to the agent as JSON, allowing the agent to recover and complete its investigation successfully.

#### What Broke and Why

SimpletonAgent started its investigation by trying to inspect the `otel_logs` table schema — a sensible first step:

```
18:15:57.143 INFO src/agents/tools/query-otel.tool.ts:44 [SimpletonAgent] queryOtel {
  sqlPreview: 'DESCRIBE otel_logs'
}
```

The `queryOtel` tool (line 17) appended ` LIMIT 500` to every query that didn't already contain a LIMIT clause, without checking whether the query was a DDL statement. The ClickHouse client library then appended ` FORMAT JSONEachRow`. The final query sent to ClickHouse was:

```sql
DESCRIBE otel_logs LIMIT 500 FORMAT JSONEachRow
```

ClickHouse rejected it immediately:

```
18:15:57.242 ERROR src/agents/tools/query-otel.tool.ts:55 [SimpletonAgent] queryOtel error {
  error: ClickHouseError: Syntax error: failed at position 26 (500) (line 1, col 26):
    500 FORMAT JSONEachRow. Expected end of query.
  code: '62',
  type: 'SYNTAX_ERROR'
}
```

Position 26 is exactly where `500` appears in the malformed query — `DESCRIBE otel_logs ` is 19 characters, `LIMIT ` is 6 more, putting `500` at position 25–27. Note that the `(500)` in the error message is **not** an HTTP 500 status code; it is the literal `500` value from `LIMIT 500` that ClickHouse encountered and could not parse in that position. `DESCRIBE` is a DDL statement that doesn't support `LIMIT` or result formatting clauses at all.

#### Recovery

The tool's try-catch block caught the `ClickHouseError` and returned it to the LLM as a structured JSON error response rather than crashing. SimpletonAgent understood the error, abandoned the `DESCRIBE` approach, and fell back to a `SELECT` query instead:

```
18:15:59.018 INFO src/agents/tools/query-otel.tool.ts:44 [SimpletonAgent] queryOtel {
  sqlPreview: 'SELECT * FROM otel_logs LIMIT 1'
}
```

That query succeeded. The agent continued its investigation through 24 episodes, queried ClickHouse multiple times successfully, browsed the codebase — including reading `query-otel.tool.ts` directly — and completed with `FOAM_ISSUE_SOLVE_SUCCEEDED` at `18:19:10`.

#### Fix

In `query-otel.tool.ts` line 17, check whether the query starts with a DDL keyword before appending `LIMIT`:

```typescript
const isDDL = /^\s*(DESCRIBE|SHOW|EXPLAIN|CREATE|DROP|ALTER|TRUNCATE)/i.test(sql);
if (!isDDL && !sql.toUpperCase().includes('LIMIT')) {
    sql += ' LIMIT 500';
}
```

This prevents `LIMIT` from being appended to `DESCRIBE`, `SHOW`, `EXPLAIN`, and other DDL statements that don't support it.
