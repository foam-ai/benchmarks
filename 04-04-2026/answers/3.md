### RCA: Issue Solver Run Fails Because Sentry Project Is Missing from Database

#### TL;DR

The webhook was received and processed normally up until the point where the issue solver tried to build a run. At that point it looked up projectId `4509119107891200` in the database and found nothing — the project was either never saved during onboarding or was deleted. The run was never created and the error bubbled up unhandled.

#### What Broke and Why

Everything upstream succeeded — the webhook was received, the lock was acquired, the issue was fetched from Sentry, uploaded to S3, and passed through issue grouping. The failure happened specifically in `buildAndStoreIssueSolverRun` when it called `findSentryProjectByProjectId` to look up the project configuration:

```
Error: Sentry projectId: 4509119107891200 not found for company: longeye
  with installationId: 2169a967-cd48-4097-bcdc-e1bbcbf59631

at findSentryProjectByProjectId (mongodb/services/sentry.service.ts:252)
at buildAndStoreIssueSolverRun (services/issue-solver/factory.ts:158)
at runSolverPipeline (routers/sentry/webhook.ts:505)
```

`findSentryProjectByProjectId` in `sentry.service.ts` queries the `SentryProjectCollection` for a matching `(installationId, projectId)` pair. When nothing is found, it throws immediately with no fallback:

```typescript
export async function findSentryProjectByProjectId(
    installationId: string,
    projectId: string,
    companyName?: string,
): Promise<SentryProjectDocument> {
    const connection = await connectToDatabase();
    return await connection.withSession(async (session) => {
        const sentryProjectCollection = new SentryProjectCollection(session);
        const project = await sentryProjectCollection.findSentryProjectByProjectId(
            installationId,
            projectId,
        );
        if (!project) {
            throw new Error(
                `Sentry projectId: ${projectId} not found for company: ${companyName} with installationId: ${installationId}`,
            );
        }
        log().info(`Successfully found project ${projectId} for installation ${installationId}`);
        return project;
    });
}
```

The "success" log is a red herring.** The log line `Successfully found project 4509119107891200 for installation 2169a967-...` at `sentry.service.ts:279` is emitted by `safeFindSentryProjectByProjectId`, which unconditionally logs this message regardless of whether a project was actually found — it logs "success" even when the result is `null`. This log is therefore NOT evidence that the project document exists in the database, and any analysis that treats it as proof of existence is invalid. There is no evidence the project was present at all. Additionally, the `companyName?` parameter in `findSentryProjectByProjectId` is only used in the error message — it is never used to query the database, so both functions run the same query, confirming the project is simply not present in the DB.

`buildAndStoreIssueSolverRun` calls `findSentryProjectByProjectId` which throws when a project is not found. The project row for `4509119107891200` does not exist in the database — either it was never persisted during the onboarding flow, or it was deleted after the fact. Projects are written via `insertSentryProject` during onboarding:

```typescript
export async function insertSentryProject(sentryProject: SentryProjectDocument): Promise<void> {
    const connection = await connectToDatabase();
    return await connection.withSession(async (session) => {
        const sentryProjectCollection = new SentryProjectCollection(session);
        await session.withTransaction(async () => {
            const success = await sentryProjectCollection.insertSentryProject(sentryProject);
            if (!success) {
                throw new Error('Failed to insert Sentry project object');
            }
        });
        log().info(`Successfully inserted sentry project ${sentryProject.projectId}`);
    });
}
```

If this step silently failed or was skipped during onboarding for `longeye`, the project row would never exist, and any subsequent webhook for that project would fail the same way.

#### Fix

**Immediate:** Manually re-sync the missing project for `longeye` by re-running the onboarding flow or directly inserting the project record for `projectId: 4509119107891200` with `installationId: 2169a967-cd48-4097-bcdc-e1bbcbf59631`.
