### RCA: `queryOtel` tool returned non-string objects, causing AI SDK `.match()` crash

#### TL;DR

PR #401 (`54dd1780`, 2026-03-18 01:37 UTC) changed `query-otel.tool.ts` so the tool output `result` was no longer a string: it widened the schema from `z.string()` to `z.unknown()` and switched from `result.text()` to `result.json()`, producing raw ClickHouse row JSON objects. That non-string tool output is the root cause. The Vercel AI SDK expects tool results to be text and internally calls `.match()` on them, so when it received an object it crashed with `TypeError: text2.match is not a function`.

#### What Broke and Why

PR #401 (`54dd1780`) changed the `queryOtel` tool to return raw ClickHouse row objects:

```diff
- result: z.string().describe('The result of the ClickHouse SQL query.')
+ result: z.unknown().describe('The result of the ClickHouse SQL query.')
...
- return { result: telemetry.xml, ... }  // string
+ return { result: rows, ... }           // Array<Object>
```

The Vercel AI SDK requires tool results to be strings — it serializes them into the next LLM turn as text content and internally calls `.match()` / `.matchAll()` on that content (minified variable `text2`). With `result` now an object instead of a string, that non-string output became the direct root cause of:

```
TypeError: text2.match is not a function
```

#### Fix
The fix is two lines in query-otel.tool.ts:
Change result.json() back to result.text() — ClickHouse's JSONEachRow format already produces a valid newline-separated string, no manual serialization needed.
Restore outputSchema.result: z.string() to match.
