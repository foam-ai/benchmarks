### RCA: ClickhouseSqlAgent failing with TPM exhaustion in `mewtwo/src/agents/simpleton/index.ts`

#### TL;DR

`ClickhouseSqlAgent` failed during an eval run on 2026-01-22 because 7 tool calls in a single `streamText` iteration accumulated ~88K+ chars of query results in ~40 seconds, exhausting the organisation's Anthropic TPM budget (4,000,000 tokens/min). When the nudge mechanism triggered a second `streamText` call with the full accumulated context, both the Anthropic API and the Bedrock fallback returned rate limit errors. It did not self-recover.

#### What Broke and Why

There are two compounding levels of context accumulation built into `SimpletonAgent`:

**Level 1 — SDK internal (within a single `streamText` call):** The Vercel AI SDK accumulates `responseMessages` internally across each step. Every tool result is appended before the next LLM call, so by step 7 the SDK is sending: initial context + all 6 previous tool results. This is not visible in application code — it happens inside the SDK.

**Level 2 — Agent external (across nudge iterations):** The `messages` array on line 78 of `simpleton/index.ts` persists for the lifetime of the `while` loop. When the nudge fires, the next `streamText` call receives the entire accumulated history from iteration 1 on top of the new nudge message.

```typescript
// mewtwo/src/agents/simpleton/index.ts
// Line 78: messages array created ONCE, never reset
const messages: ModelMessage[] = [
  { role: 'user', content: initialMessage },
];

while (nudgeCount <= maxNudges) {
  const result = await this.streamText({
    model: registry.languageModel('bubbles:agent'),
    messages,   // ← same array passed every iteration, grows unboundedly
    tools,
    stopWhen: [stepCountIs(this.maxSteps), hasToolCall('completeTask')],
  });

  // Lines 148-162: each nudge pushes MORE content onto the same array
  messages.push({ role: 'assistant', content: lastStepText });
  messages.push({ role: 'user', content: 'You must call completeTask...' });
}
```

In this run, the agent made 7 tool calls in iteration 1. Two ClickHouse queries failed with invalid column names, adding error text to context with no useful signal:

```
// EXCEPTION — 2026-01-22 21:54:05.512
Error: Unknown expression identifier `timestamp` in scope
  SELECT timestamp, body, severity_text ... FROM otel_logs WHERE ...

// EXCEPTION — 2026-01-22 21:54:08.610
Error: Unknown expression identifier `Attributes` in scope
  SELECT Timestamp, Body, SeverityText, ServiceName, ResourceAttributes, Attributes
  FROM otel_logs WHERE ...
```

The subsequent successful queries then returned large payloads — query 4 returned 37,854 chars and query 5 returned 50,034 chars (truncated). By the time the nudge fired at `21:55:07`, the SDK had been sending a growing context window across all 7 steps, consuming TPM budget throughout. When the nudge triggered a new `streamText` call with the full accumulated `messages` array, the remaining TPM budget was already gone.

The error cascade when nudge 2 called `streamText`:

#### Fix

Add context management to `SimpletonAgent` to bound the size of tool results before they are appended to the `messages` array — either by truncating large tool outputs or by enforcing a per-call token ceiling. Without this, any run where tool calls return large payloads will exhaust the TPM budget before the nudge can complete.
