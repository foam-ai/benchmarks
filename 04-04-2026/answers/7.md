### RCA: `foam_wrapper` ModuleNotFoundError in Exception Polling Worker (`drain3-pyodide.service.ts`)

#### TL;DR

The Pyodide Python runtime failed to load `foam_wrapper` across all services because `getProjectRoot()` in `src/services/drain3-pyodide.service.ts` computed the wrong vendor directory path. A change to use `import.meta.url` with only two levels of `..` traversal resolved to `/app/mewtwo/dist/vendor/drain3` instead of the correct `/app/mewtwo/vendor/drain3`. Every exception polling job for every service failed on every retry. The fix was a one-line path depth correction (PR #333).

#### What Broke and Why

The `getProjectRoot()` function in `src/services/drain3-pyodide.service.ts` was changed from `findUpSync('package.json')` to a `fileURLToPath(import.meta.url)`-based traversal. The commit introducing the bug is 13e460e338f57c9900a1328ccc134d75b16c188f. The PR diff shows the exact change at line 117:

```typescript
// mewtwo/src/services/drain3-pyodide.service.ts
// REMOVED (lines 114–121):
const packageJsonPath = findUpSync('package.json', { cwd: process.cwd() });
if (packageJsonPath) {
  return path.dirname(packageJsonPath);
}
return process.cwd();

// ADDED (lines 114–117):
// This file is at: mewtwo/src/services/drain3-pyodide.service.ts
const currentFileDir = path.dirname(fileURLToPath(import.meta.url));
// Navigate up: services -> src -> mewtwo (or dist/src/services -> dist/src -> dist -> mewtwo)
return path.resolve(currentFileDir, '..', '..');  // ← BUG: only 2 levels up
```

The comment on line 116 correctly describes the production traversal as **4 steps** (`dist/src/services → dist/src → dist → mewtwo`), but the code only performs **2**. In development the shallow structure (`src/services/`) means 2 levels accidentally reaches the project root. In production the compiled output lives under `dist/src/services/`, which requires a third `..` to escape `dist/`:

| Step | Dev path | Prod path |
|------|----------|-----------|
| Start (`currentFileDir`) | `.../mewtwo/src/services` | `.../mewtwo/dist/src/services` |
| `..` | `.../mewtwo/src` | `.../mewtwo/dist/src` |
| `..` | `.../mewtwo` ✅ | `.../mewtwo/dist` ❌ |
| `..` *(missing)* | — | `.../mewtwo` ✅ |

That incorrect root was then used to construct the vendor path passed to Pyodide as a host mount:

```
# Path the worker attempted to mount — does not exist
hostPath '/app/mewtwo/dist/vendor/drain3'

# Correct path where Python modules actually live
/app/mewtwo/vendor/drain3
```

Because the mounted directory did not exist, Pyodide could not find `foam_wrapper` and threw on the first Python import:

```
ModuleNotFoundError: No module named 'foam_wrapper'
  File "/lib/python313.zip/_pyodide/_base.py", line 411, in run_async
    coroutine = eval(self.code, globals, locals)
  File "<exec>", line 2, in <module>
```

This propagated up through `foam-issue-batch-processor.service.ts:286` and then through `MonitoredWorker.processExceptionPollingJob` at `exception-polling.worker.ts:327`, failing every BullMQ job for every service (`webapp-browser`, `porygon-browser`, `mewtwo`, `mono`) on every poll cycle:

```

{ error: PythonError: ... ModuleNotFoundError: No module named 'foam_wrapper' }

2026-03-02 02:33:32.711 ERROR src/services/foam-issue-batch-processor.service.ts:286
Batch processing failed for 674e5380f251f603c5ef1847:mewtwo
{ error: PythonError: ... ModuleNotFoundError: No module named 'foam_wrapper' }

2026-03-02 02:33:39.335 ERROR src/services/foam-issue-batch-processor.service.ts:286
Batch processing failed for 674e5380f251f603c5ef1847:mono
{ error: PythonError: ... ModuleNotFoundError: No module named 'foam_wrapper' }
```

#### Fix

Add the missing `..` to `getProjectRoot()` at line 117 of `src/services/drain3-pyodide.service.ts` so the traversal correctly escapes `dist/` in the production build:

```typescript
// src/services/drain3-pyodide.service.ts — line 117, FIXED (PR #333)
const currentFileDir = path.dirname(fileURLToPath(import.meta.url));
// Navigate up: services -> src -> mewtwo (or dist/src/services -> dist/src -> dist -> mewtwo)
return path.resolve(currentFileDir, '..', '..', '..');  // ← 3 levels, not 2
```
