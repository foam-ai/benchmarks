### RCA: Elasticsearch Dynamic Mapping Type Conflict on `arg_*` Fields in `mewtwo` Transport

#### TL;DR

Elasticsearch's dynamic mapping had already locked `arg_0` as type `long` from a prior numeric log call. When a later log call passed the raw source code string `log().info('Creating worktree', { repoOwner, repoName, gitSha, worktreePath });` as a primitive argument, Elasticsearch rejected the document with `document_parsing_exception` because `arg_0` expected a `long`, not a string. The fix is to serialize all log arguments as explicit JSON, eliminating `arg_*` fields and reliance on dynamic mapping entirely.

#### What Broke and Why

In `mewtwo/src/elasticsearch/transport.ts`, the `elasticClient.index()` call sends log documents without explicit field mapping definitions, relying on Elasticsearch dynamic mapping to infer field types at index time. The `_processNonObjectArg` method creates positional `arg_0`, `arg_1`, etc. fields for any non-object primitive passed to a log call.

Once Elasticsearch infers a field type from the first document it indexes, that mapping is permanent for the index. Any subsequent document sending a different type to the same `arg_*` field is dropped entirely. The exception confirms two facts: `arg_0` was already mapped as `long` at the time of the failure, and the rejected value was a string:

```
ResponseError: document_parsing_exception
    Caused by:
        illegal_argument_exception: For input string:
        "log().info('Creating worktree', { repoOwner, repoName, gitSha, worktreePath });"
    Root causes:
        document_parsing_exception: [1:114] failed to parse field [arg_0] of type [long]
        in document with id 'SRB7WJsBZqWjny1Va7b8'.
        Preview of field's value:
        'log().info('Creating worktree', { repoOwner, repoName, gitSha, worktreePath });'
    at SniffingTransport._request (.../node_modules/@elastic/transport/src/Transport.ts:606:17)
    at async ElasticsearchTransport.processQueue (/elasticsearch/transport.ts:108:17)
    at async Timeout._onTimeout (/elasticsearch/transport.ts:57:17)
```

The rejected value is the source code expression `log().info('Creating worktree', { repoOwner, repoName, gitSha, worktreePath });` being passed as a raw primitive argument to a log call rather than wrapped in an object. Because `_processNonObjectArg` maps it to `arg_0`, and `arg_0` was already locked as `long` from a prior numeric log call, Elasticsearch drops the entire document. What specific call originally locked `arg_0` as `long` is not present in the available exception data.

Because `arg_0` is reused across all log calls regardless of what primitive is passed, any numeric log call anywhere in the codebase poisons the field type for all future string log calls against the same index.

#### Fix

Replace the `_processNonObjectArg` dynamic field approach in `mewtwo/src/elasticsearch/transport.ts` with explicit JSON serialization so all log arguments are stored in a single consistently-typed field. This eliminates `arg_*` fields entirely and removes reliance on dynamic mapping:

```typescript
// mewtwo/src/elasticsearch/transport.ts — FIXED
// Instead of spreading primitives into arg_0, arg_1, etc.:
//   { arg_0: 42, arg_1: 'some string' }  ← type conflict risk

// Serialize all arguments into a single explicit JSON field:
//   { data: JSON.stringify({ args: [42, 'some string'] }) }  ← always string, no conflict
```
