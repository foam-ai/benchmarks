### RCA: Property Name Mismatch Causes Empty Solution to Be Uploaded to S3 in `mewtwo` Issue Solver

#### TL;DR

The issue solver side effects flow in `mewtwo` uploaded empty solution strings to S3 without validation and then marked the run as `completed`, implying success. When the frontend fetched the issue, the backend returned `{ solution: '' }` from the empty S3 file, and the page component in `porygon` threw a hard error on the empty string. The root cause is a TypeScript property name mismatch: the caller passed `solverResult` but `runSideEffects` destructured `result`, so `result` was always `undefined`.

#### What Broke and Why

The call site in `mewtwo/src/services/issue-solver/index.ts` passes `solverResult` using shorthand syntax:

```typescript
await runSideEffects({
    run: updatedRun,
    customer,
    solverResult,   // shorthand for { solverResult: solverResult }
    dbOnlyMode: options.dbOnlyMode,
    notificationsEnabled: options.notificationsEnabled,
});
```

But `runSideEffects` in `mewtwo/src/services/issue-solver/side-effects/index.ts` destructures `result`, not `solverResult`:

```typescript
export const runSideEffects = wrapTraced(async function runSideEffects({
    run,
    customer,
    result,         // expects "result" — no match in the passed object, always undefined
    dbOnlyMode = false,
    notificationsEnabled = false,
}: {
    run: IssueSolverRunDocument;
    customer: Customer;
    result: string;
    ...
```

`result` is `undefined` on every call. It then flows directly into `uploadSolutionToS3`:

```typescript
const issueIdentifier = run.foamIssueId?.toString() || 'unknown';
solutionS3URL = await uploadSolutionToS3(customer._id, runId, issueIdentifier, result);
```

`uploadSolutionToS3` in `mewtwo/src/services/issue-solver/side-effects/issue-solver-s3.ts` has no guard either — it writes whatever it receives, producing a 0-byte `.tar.gz` file in S3:

```typescript
export async function uploadSolutionToS3(
    customerId: mongoose.Types.ObjectId,
    runId: string,
    issueIdentifier: string,
    result: string,
): Promise<string> {
    const s3Path = `${customerId.toString()}/${issueIdentifier}/${runId}.tar.gz`;
    const s3Url = await uploadToS3(FoamBucketType.SOLUTION_TEXT, s3Path, result, 'application/gzip');
    // ...
    return s3Url;
}
```

`setIssueSolverRunSuccessStatus` then unconditionally marks the run `completed` — regardless of whether anything was actually produced.

That 0-byte file then poisons every downstream read. When the frontend requests the issue, the `GET /:issueId` handler in `mewtwo/src/routers/issues.ts` finds the `COMPLETED` run, reads the file back via `getFromS3UrlAsText` — which returns `''` — and sends it to the frontend with no guard:

```typescript
const solutionS3URL = await findLatestSolutionS3URLByFoamIssueId(issue._id);
const solutionText = solutionS3URL ? await getFromS3UrlAsText(solutionS3URL) : '';
const formattedIssue: FormattedIssue = {
  // ...
  solution: solutionText,
};
```

The page component in `porygon/app/(platform)/issues/[issueId]/page.tsx` treats an empty solution on a completed run as an unexpected state and throws:

```typescript
if (issue.solution === '') {
  throw new Error(`Issue ${issueId} has an empty solution string`);
}
```

#### Fix

Rename the property at the call site in `mewtwo/src/services/issue-solver/index.ts` to match what `runSideEffects` destructures:

```typescript
await runSideEffects({
    run: updatedRun,
    customer,
    result: solverResult,   // ← explicit mapping, not shorthand
    dbOnlyMode: options.dbOnlyMode,
    notificationsEnabled: options.notificationsEnabled,
});
```
